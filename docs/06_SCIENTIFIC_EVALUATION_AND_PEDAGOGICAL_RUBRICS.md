## 1. Theoretical Framework

### 1.1 Game-Based Learning (GBL)

Game-Based Learning (GBL) refers to the use of digital or non-digital games as the primary vehicle for achieving defined learning objectives (Plass, Homer & Kinzer, 2015). GBL is distinguished from passive multimedia learning by its emphasis on active, consequence-driven engagement: players make decisions, receive immediate feedback, and iterate toward mastery within a goal-structured, motivationally engaging context.

GameKhansa operationalises GBL through:
1. **Content integration** — mathematical operations and English vocabulary are not appended to the game; they ARE the game's core decision mechanism
2. **Consequential feedback** — incorrect answers trigger a physically tangible consequence (vehicle repulsion) rather than an abstract "wrong" indicator
3. **Mastery orientation** — gates cannot be bypassed; the learner must achieve correct response before progressing

### 1.2 Constructivist Learning Theory (Piaget, 1952; Vygotsky, 1978)

| Constructivist Principle | GameKhansa Implementation |
|--------------------------|--------------------------|
| Active knowledge construction | Player steers toward answers — physical enactment of choice |
| Scaffolded difficulty (ZPD) | 6 math grade levels + 3 vocab levels calibrated to curriculum |
| Error as learning opportunity | Wrong gate → bounce → student reconsiders options |
| Social learning | Classroom play with peers; students observe and discuss choices |

### 1.3 Dual Coding Theory (Paivio, 1986)

Simultaneous verbal and visual-kinesthetic encoding enhances memory:

| Verbal Channel | Non-Verbal Channel |
|---------------|-------------------|
| Question text (math expression / English word) | Vehicle approaching gate — spatial-kinetic encoding |
| Answer option text in portal | Racing environment visual context |
| Gold celebration banner text | Rainbow aura, confetti — emotional-visual encoding |
| Audio SFX feedback | Procedural sound — auditory channel |

### 1.4 Flow Theory (Csikszentmihalyi, 1990)

The optimal learning state ("flow") occurs when challenge closely matches skill. GameKhansa achieves flow through:
- **Challenge scaling:** 3 discrete difficulty tiers per subject, selectable per session
- **Immediate feedback:** Gate resolution within milliseconds of player contact
- **Clear goals:** Each gate presents an unambiguous question with four concrete options
- **Sense of control:** Player physically steers toward chosen answer — embodied decision-making

### 1.5 Self-Determination Theory (Deci & Ryan, 2000)

| Basic Need | GameKhansa Feature |
|-----------|-------------------|
| **Autonomy** | Vehicle choice, edu mode toggle (E key), grade/level selection |
| **Competence** | Graduated difficulty, high-score tracking, educational report card, achievement titles |
| **Relatedness** | Classroom multiplayer use; teacher facilitation; parental involvement |

## 2. Bloom's Taxonomy Alignment

### 2.1 Cognitive Domain Mapping

| Bloom's Level | Description | GameKhansa Mechanic |
|---------------|-------------|---------------------|
| **1. Remember** | Recall facts | Recognise arithmetic facts; recall English word meanings |
| **2. Understand** | Interpret meaning | Parse math expression; interpret English word in context |
| **3. Apply** | Use knowledge | Select correct gate lane under time/traffic pressure |
| **4. Analyse** | Distinguish options | Evaluate 4 answer options; eliminate distractors |
| **5. Evaluate** | Justify choice | Post-session reflection: "Why did I choose that answer?" |
| **6. Create** | *(Post-game extension)* | Students create their own quiz questions (teacher activity) |

> **Primary levels targeted in-game:** Remember (Level 1), Understand (Level 2), Apply (Level 3), Analyse (Level 4).

### 2.2 Bloom's Evidence

- **Remember:** 1,000+ vocabulary exposure events per session; math facts repeated across multiple gates
- **Understand:** Question text requires parsing mathematical expression or English word in isolation
- **Apply:** Decision must be executed under real-time pressure (moving traffic, approaching gate)
- **Analyse:** Three distractors per question require active elimination of incorrect options

## 7. Learning Outcomes Assessment Design

### 7.1 Pre-Test / Post-Test Framework

```
Week 0 → PRE-TEST (40 items: 20 Math + 20 Vocab)
    ↓
Weeks 1–4 → INTERVENTION (GameKhansa, 3 sessions/week)
    ↓
Week 5 → POST-TEST (parallel form, same blueprint)
    ↓
Week 9 → RETENTION TEST (optional: delayed recall)
```

### 7.3 Proposed Learning Gain Calculation

$$\text{Normalised Gain} = g = \frac{\text{Post-test} - \text{Pre-test}}{100 - \text{Pre-test}}$$

- $g > 0.70$: High gain
- $0.30 \leq g \leq 0.70$: Medium gain
- $g < 0.30$: Low gain

## 9. Recommendations for Classroom Integration

### 9.1 Weekly Schedule (Recommended)

| Day | Activity | Duration |
|-----|---------|---------|
| Monday | GameKhansa session — Math mode, grade-appropriate | 20 min |
| Wednesday | GameKhansa session — Vocab mode, level-appropriate | 20 min |
| Friday | Post-game reflection + vocabulary review discussion | 15 min |

### 9.2 Teacher Facilitation Tips

1. **Before session:** Set grade/level using keyboard (1/2/3) and mode (E); brief students on controls
2. **During session:** Observe which questions cause most wrong-gate bounces → target for review
3. **After session:** Ask students to share 3 English words or math facts they learned
4. **Weekly:** Compare game scores and accuracy percentages (proxy for learning progress)
5. **Monthly:** Administer short written quiz to confirm retention beyond game context

### 9.3 Parental Guidance

GameKhansa is designed as a **supplementary learning tool**, not a replacement for classroom instruction. Parents are encouraged to:
- Sit with their child for the first session to understand the mechanics
- Ask their child to explain the math answers or English words encountered
- Use the educational report card to start conversations about progress
- Limit sessions to 20–30 minutes to manage screen time appropriately
